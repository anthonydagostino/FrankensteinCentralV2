# Decisions

One line per choice the spec left open, in the order they were made.

- Python 3.12 in the Docker image; local development also works on 3.13 (no 3.12 only syntax is used).
- Background refresh uses plain asyncio tasks (one loop per integration) rather than APScheduler, to keep the dependency list short.
- `fetch()` reports partial data by raising `Degraded(data, message)`; the cache stores the data with status `degraded`.
- Firefly mock data is generated by `backend/app/fixtures/generate_firefly.py` into API shaped JSON anchored on 2026-10-20; `mock()` shifts every date by the number of days between the anchor and today so the mock dashboard always looks current.
- The kiosk cookie is set by the SPA fallback handler when `/kiosk?token=...` carries the correct token, so no extra API round trip is needed.
- Tailwind CSS 3.4 (PostCSS) rather than Tailwind 4, because the 3.x config format is the most widely documented.
- The `.env` file is loaded from the repository root (parent of `backend/`), both locally and in the container (`/app/.env` is not needed in Docker because compose passes `env_file`).
- Firefly transactions are fetched once per refresh for the whole window `[Jan 1 of the current year minus 60 days, today]` through `/api/v1/transactions`, then split per account in memory. Card specific endpoints are not needed.
- Login rate limiting is an in-memory sliding window per client IP (5 per minute), reset on restart.
- Password hashing uses `bcrypt` directly.
- Finance pace compares month-to-date spend with last month's spend through the same day number, as the spec says; when last month's value is zero the pace is reported as `null`.
- The benefits engine was built before the frontend (spec Phase 4 before Phase 3) so the UI could be written against the final API shape; commit history reflects that order.
- A card account is an asset account with role `ccAsset` (balance negative when owed) or a liability of type debt or credit card; "owed" is the absolute value, and a credit balance on a ccAsset shows as zero owed.
- Generic credit markers (credit, amex, american express, platinum, stmt cr) are matched only against the description and notes, never against account names, because the card's own account name ("Amex Platinum") would otherwise turn every refund into a statement credit. Merchant and credit patterns match description, notes, and the counterparty name.
- A withdrawal counts as a clawback only when it matches a credit pattern and also contains credit, reversal, adjustment, rev, or clawback; otherwise loose credit patterns such as `fhr` would flag the hotel prepayment itself as a clawback.
- Once a period's attributed credits reach the cap, the leftover unmatched amounts of its purchases are zeroed, so later credits attach to purchases in later periods (monthly benefits with purchases above the cap would otherwise cascade credits into the wrong month).
- A credit that matches no purchase (attributed by credit date) still consumes unmatched eligible spend in that period, so pending and missing credit stay honest for benefits that credit a monthly sum (Dunkin').
- Future periods (start after today) are left out of `history`; the year view shows the current period and the periods that already started, plus last year's periods that still have evidence.
- `expiring_soon` requires at least $1.00 remaining, so a $0.19 rounding leftover (Walmart+ cap 14.00 vs 13.81 charged) does not raise an attention item.
- Manual benefits with no entry keep status `manual` even after the period ends (spec scenario 12); their missing cap still counts as left on the table.
- The cache mirror records whether an entry came from mock or live mode; on startup an entry from the other mode is discarded so mock data is never shown as "last good" live data.
- An empty value in `.env` for a non-string setting (for example `MOCK_PLEX=`) means "use the default".
- Attention items for benefits are blurred along with other amounts when privacy blur is on, since their titles contain dollar amounts.
- Chart animations are disabled so the kiosk does not animate on every poll.
- Hourly day or night icons are derived from the daily sunrise and sunset because the hourly `is_day` field is not requested.
- Plex deep links use the formats in the spec; they could not be tested against a live server here, so if an item link fails open the server link instead.
- No live service and no Docker daemon were reachable from the build environment, so Phases 5 and 6 were verified with respx against recorded fixtures only; `docker compose config` and a wheel build of the backend were verified, `docker compose build` was not.
- Recurring charge detector: a cluster needs 60 percent of its intervals near one cadence; weekly and biweekly clusters, and any cluster seen only twice, must repeat the exact amount (so two grocery runs never look like a subscription); monthly and slower clusters may vary up to 20 percent, or 60 percent when at least three charges exist (utilities), and anything wider is dropped.
- Charges through Apple, PayPal, Google, Square, and similar processors are clustered by descriptor plus amount, because the descriptor hides the real merchant.
- Yearly cost is the latest amount times the cadence's periods per year, not the measured interval, so a 31 day gap does not change the annual figure.
- A subscription is "lapsed" after 1.6 intervals without a charge and "new" when first seen within 60 days. Only price increases of 5 percent or more raise an attention item.
- Ignored recurring charges are stored as a newline separated list in the settings table under `recurring_ignore`.
- Lock-In integration reads `/api/summary` for the headline numbers and `/api/export` (read only, same token) for the Monday to Sunday squares and the 60 day weight trend; if the export call fails the widget still renders from the summary with status `degraded`.
- Streak risk is derived in Frankenstein: `at_risk` when the sessions still needed for 5 equal the days left in the week (today included), `lost` when they exceed them, `safe` once 5 are done. The attention strip only warns for `at_risk`, and for `lost` only when a streak exists to lose.
- The weigh-in nudge fires between 10 AM and 10 PM New York time when the latest weigh-in is not dated today.
- "On track" for weight means the weekly change is within 0.5 lb per week of the phase target.
- Plex discovery: with `PLEX_URL` empty the adapter calls `plex.tv/api/v2/resources` with the account token, picks the server by `PLEX_SERVER_NAME`, else the first owned server, else the first one marked present, and uses that resource's `accessToken` (required for servers shared by other people). Connections are tried public first, then local, then relay, each as the plex.direct uri and the raw address, with a 6 second timeout; the working one is cached for an hour and dropped on the next failure so a changed public IP triggers rediscovery.
- The mock Plex server is presented as a shared one ("Absolute Cinema", shared by eddiedlugosz) to match Anthony's setup.
- Quality pass (November 2026): `ruff`, `ruff format`, and `mypy` run in `scripts/test.sh` and therefore in CI; the rule set lives in `backend/ruff.toml`.
- A 401 or 403 counts as a rejected token only when the request carried credentials (Authorization or X-Plex-Token). Anonymous calls (NWS, a locked down docker-socket-proxy endpoint) report the plain HTTP status instead of telling the user to regenerate a token.
- Firefly listings stop at 200 pages (20,000 rows); hitting the cap marks the refresh degraded with the rows fetched so far rather than silently truncating.
- The Firefly transaction window follows the current year only. `GET /api/benefits?year=<earlier>` therefore sees just the rows inside the window; fetching a second year of history was not added (it would double memory and API calls for a view that is rarely opened).
- The kiosk cookie carries a fingerprint of `KIOSK_TOKEN`, so rotating the token revokes every cookie issued before it. Changing `SECRET_KEY` still revokes everything.
- Link tiles and probes resolve only env var names that end in `_URL`, because their values reach the browser or the status envelope.
- Plex rails (recently added, on deck, libraries) are cached for 15 minutes only when every rail call succeeded, so a server that recovers is picked up on the next 30 second refresh.
- Vaultwarden backup age scans the backup directory in a worker thread at most every 5 minutes; the directory can be large or on NFS.
- Docker inspect payloads are cached for 5 minutes but refetched as soon as the list state of a container changes, so exit codes and restart counts never lag a state change.
- Derived views (benefits per year, finance summary, recurring charges) are memoized until the next Firefly refresh, override change, or day change; the finance summary is additionally keyed to the minute because it reports freshness in hours.
- SQLite runs with `synchronous=NORMAL` under WAL: a power loss can lose the last cache writes but cannot corrupt the file, and the event loop no longer fsyncs on every cache write.
- The frontend privacy blur takes the server setting as its source of truth (no localStorage), so every device agrees after a toggle on the dashboard; the kiosk toggle stays local to the kiosk session.
- Security headers on every response: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, and `Cache-Control: no-store` on `/api/*`. Embedding the kiosk in another site's iframe is therefore not supported.
- `/api/auth/me` reports `password_configured` so the login page can warn when no hash is set; the value is not secret.
- The kiosk route polls `/api/auth/me` every 30 seconds while locked, so a backend that comes up after the kiosk browser does not strand it on the locked screen; the 6 hour reload lives in the same gate so it runs while locked too.
- Tailwind `ink-500` was referenced but never defined and rendered as unstyled text; it is now defined as a mid gray between `ink-400` and `ink-600`.
- Frankenstein reaches Lock-In over a shared Docker network with the fixed name `lockin`, created by the Lock-In stack and declared external here. Lock-In publishes its port on `127.0.0.1` only, so the host address does not work from inside a container, and a project prefixed network name would depend on each checkout's folder name. Frankenstein therefore needs that network to exist before it starts.
